# 記憶の索引

会話を始めたらここを読み、関係する記憶を開く。1ファイル1事実。

- [ask-only-for-irreversible](ask-only-for-irreversible.md) — 止まって許可を取るのは、消す・外へ送る・お金が動くなど戻せない操作だけ。戻せる作業は任された範囲で進める
- [check-premise-before-fixing](check-premise-before-fixing.md) — レビューの指摘を直す前に、書かれた直し方の前提が本当かを実物で確かめる
- [check-time-with-date](check-time-with-date.md) — 日誌やゴール本文に時刻を書く直前に、date で今の時刻を確かめる
- [child-goal-per-work-unit](child-goal-per-work-unit.md) — 作業は意味が閉じる区切りごとにタスクとしてAddnessに置き、終わったらすぐ完了にする
- [explain-reasons-to-ai](explain-reasons-to-ai.md) — AIへの説明（設定ファイル・ゴール本文・依頼文）は、禁止の羅列ではなく、なぜそうするかを書く
- [first-look-review](first-look-review.md) — 作った物は、要件を知らない別のAIに見せ、目が動いた順に迷った所を言わせてから本人に見せる
- [first-value-early](first-value-early.md) — 手順の多い仕事は、関心が続いているうちに最初の成果を見せる。確認を続けて挟まない
- [judge-with-one-sheet](judge-with-one-sheet.md) — 選択肢と材料が要る判断は、判断シート1枚で聞く。一言で済む問いは会話で一言
- [keep-goal-body-rich](keep-goal-body-rich.md) — ゴール本文には、決めたことと理由・分かったこと・成果物の場所・日付つきの作業記録をしっかり書く
- [let-them-say-what-is-wrong](let-them-say-what-is-wrong.md) — ダメ出しやり直しを言われたら、まず本人に何が問題かを話してもらってから作る
- [minimal-scope](minimal-scope.md) — 頼まれた範囲ぴったりに作る。ついでの拡張は作らず、提案で止める
- [no-writing-to-completed-goals](no-writing-to-completed-goals.md) — 完了したゴールには書き込まない。書く前に完了していないかを確かめる
- [place-task-before-work](place-task-before-work.md) — 何かを始める前に、Addnessで同じ話のタスクを探し、無ければタスクを置いてから始める
- [plain-words](plain-words.md) — 説明は普通の言葉で書く。自分で作った比喩や呼び名を使わない
- [readme-is-a-map](readme-is-a-map.md) — フォルダの README は地図（何の領域か・中に何がどう入っているか）だけ。進み具合はAddnessへ
- [real-examples-first](real-examples-first.md) — 事例や参考を出す時は、言葉でまとめず、実物を並べて本人に選んでもらう
- [show-before-building](show-before-building.md) — 作り込む前に、画面は絵で・文面は全文と変えた所で見せる
- [show-structure-as-pictures](show-structure-as-pictures.md) — 流れ・ツリー・今と案・比較は、文章でなく絵で見せる。絵の中の文字は少なくする
- [tasks-not-states](tasks-not-states.md) — やることを出す時は、タスクだけを出す。状態の文や、既にあるゴールの言い直しを並べない
- [verify-with-evidence](verify-with-evidence.md) — 「できました」は、終了コード・件数・画面などの実物で確かめてから言う
